# B 站自主探索的记忆归属设计 —— 统一 vs 割裂

> 核心质疑：如果 B 站记忆单独存，QQ 问她「今天在 B 站看到什么」她不记得，
> 那就违反了统一记忆和统一人格的原则。这个质疑是对的。

## 一、大肥鱼的做法（反面参考）

deepmoyu 明确隔离：发送开关、角色工具、学习经验都只在鱼模式生效；普通 DSH 会话不接收鱼人格，模式切换后撤销角色工具。它的记忆写在 <DSH_HOME>/bili-duty/，和主记忆分开。
结果就是用户说的那种割裂：鱼模式里刷到的东西，普通聊天里不一定想得起来。他们靠日报 + 记忆审核把经验慢慢沉淀，但那是另一套系统，不是统一记忆。

## 二、Kirari 现有记忆系统能提供什么

记忆有四根轴：
- 归属轴 subject：self::（关于她自己）/ person::{cp}（每个人的池）/ scene::（场合池）/ GLOBAL（常识）
- 可见性 visibility、可信度 epistemic（fact/observed/hearsay/rumor）
- 检索 resolveSubjects 只读：当前人的池 + 场合池 + self:: + GLOBAL；别人的池根本不进查询

写入铁律：身份不明时宁可不记，也不能落共享池（person::unknown 是全员共享池的坑）。也就是说：后台任务没有对话者上下文时，默认不能写 person 池。

## 三、关键判断：B 站见闻属于谁的记忆？

答案是：关于 Kirari 自己的经历，属于 self:: 池。

理由：
1. 内容是她亲眼看到的（observed）或她自己总结的，不是主人告诉她的
2. 主人问起时，典型问法是你今天在 B 站看到什么了——问的是她的经历
3. self:: 池本来就装关于 Kirari 自己、她的设定、她的成长

所以正确做法不是新建一套 B 站记忆，而是把 B 站见闻作为她的经历写进统一记忆的 self:: 池，标 source=observed、visibility 正常、可检索可联想。

## 四、但身份隔离要守住——三个边界

### 边界 1：触发者是谁
- 主人触发（QQ 私聊说去看看 B 站）→ 后台任务带 owner 身份上下文 → 记忆可写 self:: 池
- 客人/群里触发 → 不能让她替客人跑一趟然后把见闻记进 shared；P1 建议：只允许主人触发自主浏览，和现有 owner 权限一致

### 边界 2：内容是谁的
- 关于她自己刷到的视频/学到的梗/形成的口味 → self:: 池（统一记忆）
- 视频里涉及某个具体第三人隐私的内容 → 不写，或按 hearsay/rumor 降级并标 aboutPerson
- 通过弹幕/评论读到的别人说的观点 → hearsay，不能洗成她亲眼确认的事实

### 边界 3：披露分级
- 主人问起 → 正常可说（这是他的桌宠自己的经历）
- 别人问起 → 走现有 disclosureFor / _askedAbout 逻辑：可以聊，但不泄露主人相关信息
- self:: 池里的 B 站记忆不含任何用户私事，所以天然安全

## 五、推荐架构（统一记忆，不割裂）

B站扩展包（sidecar，Python）：产出结构化见闻 {title, bvid, why, takeaway, observedAt, sourceUrl}
    ↓ service.call 返回给宿主
宿主（Node，两端一致）：
  ├─ 格式化成一句人话：她今天刷到一个讲 XX 的视频，觉得 YY
  ├─ 调统一 memory.remember({ content, subject: self::<ownerUid>, source: observed, visibility: normal, identity: owner 身份 })
  └─ 写进同一套记忆库
    ↓
QQ 问今天看到啥 → 常规 memory.recall 自然召回 self:: 池 → 她记得

注意：B 站扩展包不自己管记忆，它只产出见闻。写记忆必须走宿主统一接口，这样身份归属、可信度、披露分级、检索联想全部复用现有系统，不会形成第二套记忆。

## 六、P1 的具体约束（防割裂落地清单）

1. 只读工具，不写平台（评论/私信/动态都等授权闸门）
2. 只主人能触发后台浏览（沿用现有 owner 权限）
3. 后台任务上下文带 owner 身份（uid/counterpartId/role=owner）传入 memory.remember
4. 每次浏览产出 1~3 条 self:: 池记忆（observed），不做独立记忆库
5. 记忆文本写她自己的视角和收获，不写主人让她看的——避免 person 池混淆
6. 好奇手帐/日报可作为结构化附件存在 userData/bili-notes/，但检索入口在统一记忆（记忆指向文件，不另建检索系统）
7. 切换会话/模型不影响记忆——因为它本来就在主记忆库里

## 七、结论

用户质疑成立：B 站记忆割裂会破坏统一人格与统一记忆。正确路线是——浏览能力作为扩展包，见闻作为她的经历写进统一 self:: 池，用现有的 identity / epistemic / disclosure 机制守住身份隔离。这样她在 QQ 被问起时，自然语言 recall 就能想起来，和桌宠里/控制台里问她一模一样。
